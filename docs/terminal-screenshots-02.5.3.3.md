# 02.5.3.3: Authentic color terminal screenshots

## Why we record the real CLI

Screenshots in the README must be honest recordings of PBIQ, not image-generated
mockups or colorized transcripts. The `scan` and `audit` commands use ANSI
styling when running in an interactive terminal. The `inspect --measures`
renderer is intentionally plain-text; its screenshot uses the same polished
terminal theme but does **not** invent colored result categories.

The project has one **manual-only** GitHub Actions workflow:
`.github/workflows/docs-screenshots.yml`. It checks out the public synthetic
fixtures, builds the current CLI, runs four version-controlled
[Charm VHS](https://github.com/charmbracelet/vhs) tapes in a pseudo-terminal,
and uploads four PNGs for review. Running the workflow **does not** commit
images to the repository or create a GitHub Release.

## What gets captured

| File generated by Actions | Public synthetic fixture | Expected CLI result |
| --- | --- | --- |
| `scan-color.png` | `valid-pbir-tmdl` | `STRUCTURE VALIDATION: PASS`, exit `0` |
| `inspect-measures.png` | `valid-pbir-tmdl` | `Measures inspected: 2/2`, exit `0` |
| `audit-summary-color.png` | `valid-pbir-tmdl` | `PASS WITH COVERAGE GAPS`, exit `0` |
| `audit-warning-color.png` | `warning-pbir-tmdl` | `FAIL (WARNING POLICY)`, exit `1` |

The tapes live in `assets/vhs/`. They set the same dark **Cactus Obsidian**
color palette and a standard JetBrains Mono font. VHS records real terminal
output, not a fake post-processing recolor. The shell function `pbiq()` in the
hidden setup simply invokes the built .NET CLI DLL and keeps the demo command
short. No private `.pbip` path or shell history is used.

The media generator requires **VHS, a browser, ttyd and ffmpeg**. The official
`charmbracelet/vhs-action` sets up the recording environment for GitHub Actions;
no local VHS installation is required for the recommended workflow.

## Step 1: commit the capture infrastructure

From the repo root (PowerShell 7):

```powershell
git status --short
git add .github/workflows/docs-screenshots.yml
git add assets/vhs
git add scripts/verify-terminal-screenshots.py
git add scripts/import-terminal-screenshots.ps1
git add docs/terminal-screenshots-02.5.3.3.md

git diff --cached --check
git diff --cached --stat
git commit -m "docs(media): add reproducible color terminal captures"
git push origin main
```

Check normal CI before dispatching the screenshot workflow. There are no CLI or
xUnit behavior changes in this patch.

## Step 2: render screenshots on GitHub

```powershell
gh workflow run docs-screenshots.yml --ref main
gh run list --workflow docs-screenshots.yml --limit 3
```

Find the new run ID (`RUN_ID`) and watch it:

```powershell
gh run watch <RUN_ID>
```

If rendering fails, inspect the `Capture four real terminal frames` job and
fix its tape/workflow. **Do not** replace failed screenshots with generated
illustrations or unverified PNGs.

After a successful run, download the `pbiq-terminal-screenshots` artifact:

```powershell
$runId = <RUN_ID>
$media = Join-Path $env:USERPROFILE 'Documents\PBIQ-Terminal-Screenshots'
New-Item -ItemType Directory -Force -Path $media | Out-Null
gh run download $runId -n pbiq-terminal-screenshots -D $media
```

**Review all four images manually**. Check for legibility, expected color,
complete `scan` summary, non-clipped `inspect` rows, the correct PASS/FAIL
outcome, ASCII icon fallback (`?` characters), version labels and accidental
personal information. The images should not include paths outside the
synthetic `examples/` directory. A successful workflow alone cannot ensure
visual quality.

## Step 3: import only reviewed PNGs

```powershell
.\scripts\import-terminal-screenshots.ps1 -SourceDirectory $media

git diff --check
git diff -- README.md
git status --short
```

The importer accepts **only the four expected PNG filenames**, validates their
headers, copies them into `assets/screenshots/` and replaces the existing
README media comment with accessible Markdown image links. It is safe to run
again without adding duplicate README sections.

Open README in a Markdown preview. Confirm the big `scan` screenshot looks good
and the `inspect` and `audit` screenshots expand correctly. The PNGs only use
public fixture content, but review them before publication anyway.

```powershell
# Only after visual review
git add README.md assets/screenshots
git diff --cached --check
git diff --cached --stat
git commit -m "docs(media): add verified PBIQ terminal screenshots"
git push origin main
```

This is a **separate commit** because image assets must be generated by the
real application first. The screenshot binaries are not included in the
infrastructure patch.

## Tape syntax preflight and troubleshooting

Before running the costly screenshot workflow, check the source tapes without
installing VHS:

```powershell
python scripts/check-vhs-tapes.py assets/vhs
```

The preflight catches malformed `/regex/` delimiters in `Wait+Screen` lines and
missing screenshot commands. In a VHS tape, an unescaped slash **inside** the
regex can terminate it prematurely. For example, use
`Wait+Screen@30s /Measures inspected:/` rather than a pattern containing the
literal `2/2`. The CI workflow runs this check immediately after checkout,
then performs the official `vhs validate` before rendering.

If a screenshot workflow still fails, inspect the `Capture four real terminal
frames` step in the Actions job before changing any PBIQ code. Node.js runtime
migration warnings from `charmbracelet/vhs-action` are informational unless
that action actually fails. Do not change the recording format to mock data.

## Local alternative / regeneration

On Linux/WSL with .NET 10, VHS and its dependencies installed, from the repo
root:

```bash
dotnet build -c Release -warnaserror
mkdir -p assets/screenshots assets/demos
unset NO_COLOR
vhs validate assets/vhs/*.tape
vhs assets/vhs/scan.tape
vhs assets/vhs/inspect-measures.tape
vhs assets/vhs/audit-summary.tape
vhs assets/vhs/audit-warning.tape
python3 scripts/verify-terminal-screenshots.py assets/screenshots
rm -f assets/demos/.capture-*.gif
```

Prefer the Actions route on Windows, because the tapes use Bash and a Linux
pseudo-terminal. Do not record from a live Power BI customer model.

## Quality bar and known polish items

- Colorful screenshots are real ANSI terminal captures; no `--no-color` or
  redirected streams are used when recording.
- `inspect --measures` remains plain text by design, even in the themed frame.
- Each artifact should be sharp, readable in GitHub light/dark mode, and have
  no cropped last row or prompt covering the report.
- The CLI's `scan` banner currently shows the short release line `v0.2.0`
  although `pbiq --version` reports the more precise `0.2.0-rc.1+SHA`.
  **Fix that mismatch before final RC screenshots**, then regenerate the PNGs.
- Some fallback status glyphs may render as `?` on some terminals. Inspect
  their appearance rather than painting over them; fix the renderer later if
  needed. Never alter text in captured output post hoc.
- Do not commit the VHS `.capture-*.gif` intermediate files. The polished,
  short hero animation belongs to **02.5.3.4**.
